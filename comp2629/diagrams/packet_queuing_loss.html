Time a packet waits behind others = queue_bytes × 8 / link_bps. Grows with buffer occupancy.

VERIFIED CALCULATIONS (v3 — reviewed & corrected)

✓ Tick = 10 ms  ← v3 bug fixed: 800 ms tick dumped 3.9 MB/tick into 500 KB buffer → false loss
✓ Arrival bytes/tick = arr_Mbps × 1e6/8 × 0.01 s (fractional accumulator, no rounding drift)
✓ Transmission bytes/tick = tx_Mbps × 1e6/8 × 0.01 s (same accumulator method)
✓ Buffer min = 200 KB — ensures arrPerTick (max 125 KB @ 100 Mbps / 10 ms) always < buffer
✓ Serialisation delay = pkt_bytes × 8 / tx_bps [ms]
✓ Queuing delay = queue_bytes × 8 / tx_bps [ms]  ← bug in v2 fixed (was ÷8 too small)
✓ Max queue delay = buf_bytes × 8 / tx_bps [ms]
✓ Loss rate = dropped_bytes / arrived_bytes × 100 (per tick, live)
✓ Actual throughput = drained_bytes/tickSec × 8 / 1e6 Mbps  ← bug in v2 fixed (was showing theoretical min(arr,tx))
✓ bufPkts = floor(buf_bytes / pkt_bytes) · pps = rate_bps / (pkt_bytes×8)
✓ Queuing delay computed before enqueue (correct: packet sees existing queue)
